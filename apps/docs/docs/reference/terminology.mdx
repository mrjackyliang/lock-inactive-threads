## Threads and Inactivity

| Term                  | Also known as                             | Definition                                                                                                                                                                 |
|-----------------------|-------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **thread**            | —                                         | An issue or a pull request. The action processes both types independently, each with its own comment, inactivity window, and lock reason.                                  |
| **inactive thread**   | —                                         | A closed, unlocked thread whose last update is older than the inactivity window. The action finds these with the search qualifiers `is:closed is:unlocked updated:<=date`. |
| **inactivity window** | `ISSUE_INACTIVE_DAYS`, `PR_INACTIVE_DAYS` | The number of days without updates before a thread counts as inactive. Set per type, both defaulting to 30.                                                                |
| **exclude labels**    | `EXCLUDE_LABELS`                          | A comma-delimited list of label names. Any thread carrying a matching label is skipped, even if it meets the inactivity threshold.                                         |

## Locking

| Term                | Also known as                         | Definition                                                                                                                                  |
|---------------------|---------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| **closing comment** | `ISSUE_COMMENT`, `PR_COMMENT`         | The comment posted to a thread immediately before it is locked. Set custom text per type, or leave them empty to use the built-in defaults. |
| **lock reason**     | `ISSUE_LOCK_REASON`, `PR_LOCK_REASON` | GitHub's native reason attached to a locked thread: `off-topic`, `resolved`, `spam`, or `too heated`. The default is `resolved`.            |
| **dry run**         | `DRY_RUN`                             | A mode enabled by setting `DRY_RUN` to `true`. The action logs which threads would be locked without commenting on or locking anything.     |

## Inputs and Outputs

| Term              | Also known as      | Definition                                                                                                                                                                     |
|-------------------|--------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **action input**  | `INPUT_*` variable | A `with:` value from the consuming workflow, surfaced to the action as an `INPUT_*` environment variable.                                                                      |
| **configuration** | —                  | The parsed object produced from the raw inputs: coerced numbers, boolean flags, a trimmed label array, and defaulted comments.                                                 |
| **log output**    | `LOG_OUTPUT`       | A mode (default `true`) that prints the found-count line (also in dry runs) and per-thread lock or skip lines during a live run. Setting it to `false` suppresses those lines. |
| **result output** | `result`           | The action's single output: `true` when the run (or dry run) completes, or `false` when one or more threads fail to lock or an unexpected error occurs.                        |
