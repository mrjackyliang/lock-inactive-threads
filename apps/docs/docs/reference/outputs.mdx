Exposes a single output that later workflow steps can read to decide what happens next.

| Name     | Description                                                    |
|----------|----------------------------------------------------------------|
| `result` | The success or failure response after the action has completed |

## Values

The `result` output resolves to one of two string values:

- `"true"` — the run completed without errors. Every <Terminology title="Any issue or pull request the action can lock" to="/docs/reference/terminology#threads-and-inactivity">thread</Terminology> was locked, skipped because it was already locked, or previewed in <Terminology title="Shows what would lock without touching anything" to="/docs/reference/terminology#locking">dry-run</Terminology> mode.
- `"false"` — one or more <Terminology title="Any issue or pull request the action can lock" to="/docs/reference/terminology#threads-and-inactivity">threads</Terminology> failed to lock, or the action threw an unexpected error

If any individual <Terminology title="Any issue or pull request the action can lock" to="/docs/reference/terminology#threads-and-inactivity">thread</Terminology> encounters an error during locking, the action continues processing the remaining <Terminology title="Any issue or pull request the action can lock" to="/docs/reference/terminology#threads-and-inactivity">threads</Terminology> and then sets `result` to `"false"` and marks the step as failed once the run finishes. An unexpected error also marks the step as failed. You'll still see per-thread details in the workflow log when `LOG_OUTPUT` is enabled.

## Reading the Output

You can reference the output in a downstream step with `steps.<id>.outputs.result`, where `<id>` matches the step's `id` field. This is useful for sending a notification or opening an issue when the action reports a failure.

```yaml title=".github/workflows/lock-inactive-threads.yml"
jobs:
  lock:
    runs-on: ubuntu-latest
    steps:
      - name: Lock inactive threads
        id: lock-threads
        uses: mrjackyliang/lock-inactive-threads@v1
        with:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Notify on failure
        if: ${{ failure() && steps.lock-threads.outputs.result == 'false' }}
        run: echo "Lock Inactive Threads reported a failure."
```

A `"false"` result also marks the step as failed, which stops later steps by default, so the `if` conditional includes `failure()` alongside the string value of `result`. That way you can gate any follow-up step — a Slack message, an issue creation, or a repository dispatch — on whether the run succeeded.
